## Description

Payroll preparation for the RestoManager platform (roadmap Phase 2). Turns
approved worked hours into a persisted, auditable **pay-period close** with the
payroll math `time-tracking` (INIT-2026-0004) leaves partial — Québec
statutory-holiday premiums, vacation indemnity (4%/6% by seniority), and
time-off pay impacts — on top of the already-computed regular + weekly-overtime
pay. Computation is asynchronous (202 + event + worker); a closed run is an
immutable payroll record, and post-close corrections carry forward as
adjustments on the next open run. Managers export a validated run as CSV or PDF
for handoff. Employeur D outbound integration and source deductions are
deferred (Phase 3). New `payroll` domain. Deterministic, no LLM.

## Scope

- New `payroll` domain in `restomanager-specs` (registered in `info.x-domains`).
- Reference data (system-seeded, read-only via API): `ProvincialLaborStandard`
  (overtime ceiling, overtime multiplier, vacation-indemnity rates + seniority
  threshold, per province + effective period) and `StatutoryHoliday` (per
  province + date). Québec seeded first; structure supports all provinces.
- `PayrollRun` aggregate with lifecycle `open → validated → closed`, computed
  asynchronously: `generatePayrollRun` (202) or the `run-generate-due-payroll-runs`
  cron creates the run in `pending`, firing `PayrollRun.Created`; the
  `on-payroll-run-created` worker computes `PayrollLine[]` and totals.
- Reconciliation gate (`validatePayrollRun`, blocking): all timesheets approved,
  no unresolved anomalies, pay config present, company overtime threshold within
  provincial bounds (≥ 20 and ≤ provincial ceiling).
- `closePayrollRun` locks the run (immutable, audited).
- `PayrollAdjustment` (retro carry-forward + manual) on open runs.
- `PayrollExport` (tracked CSV/PDF artifact) — `pdf` added to the export enum.
- AsyncAPI events (`PayrollRun.Created/GenerationCompleted/Validated/Closed`,
  `PayrollAdjustment.Created/Updated`, `PayrollExport.Created`) + a daily
  scheduled dispatcher. All payroll entities are AI Tier 0 (`operations: []`).
- Backend, restomanager-specs, restomanager_app (period-close UI + CSV/PDF
  download).

## Out of scope

- Employeur D outbound integration / provider-specific export wire format → Phase 3.
- Source deductions (income tax fed+prov, RRQ/QPP, EI/QPIP) → Employeur D.
- Tips management → IDEA-009.
- Non-Québec seeded reference data (structure supports it; added as data later).
- Multi-restaurant / multi-province single-employee aggregation (`[carry]`).
