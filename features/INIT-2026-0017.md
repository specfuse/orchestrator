## Description

Introduces a `billing` domain that runs RestoManager's subscription billing through
Stripe and grants feature access from it. A company subscribes through Stripe-hosted
Checkout, manages its payment method and invoices through the Stripe-hosted Customer
Portal, and is billed monthly on a base fee plus an amount per active employee. Stripe
webhooks are the source of truth for subscription state; entitlements are derived from
that state and are the gate paid features check.

The initiative also closes an existing hole: `Company.features` is currently writable
through `UpdateCompany`, so any CompanyAdmin can grant themselves any feature. Once
features gate paid functionality, that PATCH bypasses the paywall. Entitlement moves to
a `CompanyEntitlement` entity owned by billing, and `Company.features` becomes a
read-only derived projection.

## Scope

- The feature adds one domain, `billing`, registered in `info.x-domains` and in the two
  Spectral fast-fail enums.
- The feature adds two entities: `CompanySubscription` (aggregate — Stripe customer and
  subscription references, status, trial end, current period end, grace end, billable
  seat count, last seat sync) and `CompanyEntitlement` (one row per granted feature,
  carrying provenance: granting subscription, granted-at, expires-at, grant reason).
- Stripe holds the catalogue. The specs persist `stripeCustomerId`,
  `stripeSubscriptionId` and `stripePriceId` as references; no `Plan` or `Price` entity
  mirrors the Stripe catalogue locally.
- The feature adds five REST operations: `GET /companies/{companyId}/billing/subscription`,
  `POST /companies/{companyId}/billing/checkout-sessions` (201 + hosted Checkout URL),
  `POST /companies/{companyId}/billing/portal-sessions` (201 + hosted Portal URL),
  `GET /companies/{companyId}/entitlements` (simple list), and
  `POST /billing/stripe/webhook`, the Stripe event receiver.
- `POST /billing/stripe/webhook` carries no `x-roles`: it is authenticated by Stripe
  signature verification, not by a user principal. It is specified rather than
  hand-written in the Backend so that regeneration cannot silently break it.
- `Company.features` becomes `readOnly` and is removed from `UpdateCompany` and
  `NewCompany`. It is a flattened projection of the company's active entitlements.
- The billing path rejects a subscribe attempt when the company has no complete, valid
  billing address, and when the company's province has no active Stripe Tax
  registration.
- The feature adds eight domain events: `CompanySubscription.CheckoutStarted`,
  `.PortalOpened`, `.Activated`, `.PaymentFailed`, `.GraceExpired`, `.Cancelled`,
  and `CompanyEntitlement.Granted`, `.Revoked`. The first two exist because every
  write operation must declare what it publishes, and rather than invent a
  predicate for an event with no state behind it, the subscription row records
  when checkout and the portal were last opened — which is also the first thing
  support correlates against when a subscription changes unexpectedly.
- The feature adds one scheduled job, `run-reconcile-billable-seats`, which recomputes
  each subscribed company's active-employee count nightly and pushes the quantity to
  Stripe when it differs.
- The feature adds one event worker that updates the billable seat count when an
  employee is hired, deactivated or terminated.
- The feature adds one event worker that projects subscription state onto
  `CompanyEntitlement` rows.
- The Flutter app redirects to hosted Checkout and the hosted Portal and renders the
  current subscription state. It builds no pricing UI and no payment form.

## Out of scope

- **Write-blocking enforcement.** This initiative publishes the delinquent state and
  exposes it; refusing writes across the 24 domains is a separate initiative. Until it
  ships, the dunning policy is observable but not enforced.
- Amounts: base fee, per-employee amount, and the number of employees included in the
  base. Business config, carried on the dossier.
- A local `Plan` / `Price` mirror of the Stripe catalogue.
- An `Invoice` entity — the hosted Customer Portal is the invoice-history surface.
- Annual billing, usage metering, Connect, and Managed Payments.
- The premium features that will gate on entitlement (e.g. IDEA-007).
