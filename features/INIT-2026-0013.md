## Description

Integrate RestoManager with **Employeur D** (Solutions Paie Desjardins) so that a
restaurant operator never re-keys employee or payroll data into two systems. Phase 1
delivers a **file-export** integration (the operator downloads a generated file from
RestoManager and uploads it into Employeur D manually); a future Phase 2 replaces the
file with the Desjardins API behind the same abstract source layer.

RestoManager becomes the **HR system-of-record**: it stores the full employee payroll
profile (identity, address, banking, tax-credit codes) and formats it into the three
Employeur D import surfaces — employee master data, weekly payroll transactions, and
employee banks.

## Scope

- Extend the `employee` domain with a 1:1 `EmployeePayrollProfile` entity holding all
  payroll-grade PII (SIN, date of birth, address, banking coordinates, tax-credit
  codes, hire/termination fields), plus supporting enums (`Sex`, `Nationality`,
  `PaymentMethod`, `TaxBasicAmountCode`, `RoeReason`) and a `BankingInfo` value object.
- Add `employeurD` to the shared `ExternalSystem` enum; the 9-digit numeric matricule
  (owned by RestoManager) is stored on the existing `ExternalMapping`.
- Add a new `employeur-d` adapter domain with six entities: `EmployeurDCompanyConfig`,
  `EmployeurDGainCodeMapping`, `EmployeurDImputationMapping`, `EmployeurDExport`,
  `EmployeurDEmployeeChange`, `EmployeurDErrorCatalogEntry`.
- Support two export surfaces this initiative: **employee master** (create / modify /
  deactivate, driven by the Employeur D `Action` A/M/S column) and **payroll
  transactions** (one row per employee × gain code × week, from a closed `PayrollRun`).
- Drive exports from domain events (`Employee` created → Ajout, updated → Modification,
  terminated → deactivation; `PayrollRun.Closed` → transaction export) with a blocking
  double-import guard (Employeur D import is not idempotent).
- Classify every payroll/Employeur D entity as AI Tier 0.

## Out of scope

- **Employee banks** export surface (vacation/leave balances) — a fast-follow that
  depends on mapping the `time-off` domain balances to Employeur D bank codes.
- **Phase 2 Desjardins API** connector — the abstract source layer is designed for it,
  but the API contract is partner-gated and out of scope here.
- **Encryption at rest and Loi 25 compliance** — handled on a separate track; this
  initiative only isolates PII structurally and marks `encryptedProperties` /
  `x-classification`.
- **Gross-to-net payroll, deductions, T4/RL-1** — Employeur D performs these; RestoManager
  only supplies hours/gains and master data.
- **CCQ (construction-industry) fields** — not applicable to restaurants.
- **Multi-restaurant per-rate payroll correctness** — tracked as a payroll-domain
  follow-up (`PayrollLine` is currently single-rate); the export inherits the fix.
